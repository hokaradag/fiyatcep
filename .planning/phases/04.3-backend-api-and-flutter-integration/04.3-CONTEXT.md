<decisions>
## Implementation Decisions

### Backend API Endpoint Set
- **D-01:** All 9 routes from API-CONTRACT.md are implemented in Phase 04.3: `GET /products`, `GET /products?marketId={slug}`, `GET /products/search?q={query}`, `GET /products/{id}/prices`, `GET /markets`, `GET /markets/{id}`, `GET /discounts`, `GET /discounts?marketId={slug}`, `GET /discounts/search?q={query}`. `GET /products/{id}` and `GET /markets/search` are also in contract — implement all.
- **D-02:** Each route is added in a dedicated FastAPI router file under `backend/app/routers/`: `products.py`, `markets.py`, `discounts.py`. Registered in `main.py` via `app.include_router()`.
- **D-03:** All responses use the locked envelope: `{ "data": [...] }` for lists, `{ "data": {...} }` for single items, `{ "error": { "message": "...", "code": "..." } }` for errors (04.1 D-10). No deviations.
- **D-04:** `priceHistory` is included in ALL product responses including list endpoints — not just single-product detail (04.1 D-11 + API-CONTRACT.md §Notes 5). Use `LEFT JOIN price_history` sorted by `recorded_at ASC`.
- **D-05:** `GET /products/{id}/prices` resolves via `market_products.id → products.id → all market_products for that canonical product → current_price + is_discounted per market`. Returns `List<MarketPriceItem>` shape per API-CONTRACT.md §4.

### Dev/Demo Connectivity
- **D-06:** Flutter `api_client_provider.dart` base URL set to `http://10.0.2.2:8000/api/v1` for Android emulator development. A comment documents the physical-device alternative (`http://{LAN_IP}:8000/api/v1`). No build-time env vars needed for demo phase.
- **D-07:** FastAPI runs on `0.0.0.0:8000` (bind all interfaces) so LAN-connected physical devices can reach it with the machine's LAN IP.

### Non-Migros Market Data
- **D-08:** Accept Migros-only data for the demo. Non-Migros markets (A101, BIM, Şok, CarrefourSA, Tarım Kredi, File Market) will return empty arrays for products and discounts — the Flutter `EmptyState` widgets handle this correctly. No fake/seeded data for other markets.

### Flutter Mock→Remote Switch
- **D-09:** `repository_providers.dart` is the single flip point. Replace `ProductMockDataSourceImpl()`, `MarketMockDataSourceImpl()`, `DiscountMockDataSourceImpl()` with their Remote counterparts, each injecting `ref.watch(apiClientProvider)`. Widget tests that relied on mock providers must use `ProviderScope.overrides` to inject mock repositories (established pattern from 04.1 D-02 Phase 02).
- **D-10:** `getProductPrices(String productId)` method added to `ProductRemoteDataSource` abstract class and `ProductRemoteDataSourceImpl` — calls `GET /products/{id}/prices`, returns `List<MarketPriceItem>` (04.1 D-06).
- **D-11:** `productMarketPricesProvider` in `products_provider.dart` rewired from hardcoded mock call to `ref.watch(productRemoteDataSourceProvider).getProductPrices(productId)` (04.1 D-07).

### QUAL-06: FavoritesStore Migration
- **D-12:** `FavoritesStore` singleton migrated to `FavoritesNotifier` (`AsyncNotifier`) in Phase 04.3. With real `market_products.id` values coming from backend, the old singleton won't propagate refresh events correctly through Riverpod's dependency graph. Migration follows the 04.1 D-02 established pattern (same SharedPreferences key `favorite_products` preserved for zero data loss).
- **D-13:** `FavoritesStore` retained with deprecation comment until Phase 04.3 verification passes, then removed. Identical approach to what was planned in Phase 01.

### Verification
- **D-14:** Python pytest integration tests: spin up a test FastAPI app with a seeded in-memory SQLite DB, call each endpoint, assert response shapes match API-CONTRACT.md. Covers: products list, market filter, search, single product, cross-market prices, markets list, discounts list.
- **D-15:** Manual Flutter verification: run backend locally (`uvicorn app.main:app --reload`), trigger Migros scrape via `POST /admin/scrape/run`, open Flutter on Android emulator, confirm Products tab shows real Migros data, Market Detail shows Migros products, Price History chart populates, Cart Comparison works with real product IDs.

### Claude's Discretion
- SQLAlchemy query style for routers (ORM queries vs raw SQL via `text()`) — ORM preferred for consistency with models.py
- Whether to add a `GET /products/{id}` route (single product detail) — implement it; FlutterProductRemoteDataSourceImpl.getProductById() calls it and would otherwise fail.
- FastAPI dependency injection pattern for DB session (use `Depends(get_db)` generator per SQLAlchemy docs).
- CORS configuration for FastAPI — allow all origins for dev (no browser client yet, but good hygiene).

</decisions>

## Existing Code Insights

### Reusable Assets
- `backend/app/routers/admin.py`: Pattern for new router files — `APIRouter(prefix="...", tags=["..."])`, import inside handler to avoid circular imports, `include_router()` in main.py.
- `backend/app/models.py`: All 5 ORM models ready — Product, Market, MarketProduct, PriceHistory, Discount. Routers query via SQLAlchemy session.
- All three `*RemoteDataSourceImpl` classes: Already written with `_handleDioException`, `apiClient.get()` calls, and `json['data']` extraction — `getProductPrices()` follows the same pattern.
- `productRemoteDataSourceProvider` already wired in `repository_providers.dart` — D-10 only needs the method added to the abstract+concrete classes.

### Established Patterns
- API response envelope: `json['data']` extraction in all Flutter remote datasources — backend routers must return `{"data": ...}` wrapper.
- Error envelope: `{"error": {"message": "...", "code": "..."}}` — FastAPI exception handlers must emit this shape.
- DateTime UTC: all `recorded_at` / `valid_until` DB values stored as ISO 8601 strings with Z suffix — routers must preserve this format in JSON output.
- `ProviderScope.overrides` in widget tests — any test touching a remote-wired provider must override with mock repository (established in Phase 02).
- `isDiscounted` as SQLite int 0/1 — routers must cast to bool in JSON serialization (`bool(row.is_discounted)`).

### Integration Points
- `repository_providers.dart` line 20/30/40 (approximately): three `Provider` returns using `MockDataSourceImpl()` — these three lines are the entire flip.
- `products_provider.dart` `productMarketPricesProvider`: single call site for `getProductPrices()` rewire.
- `main.py` `app.include_router(admin_router)`: add `include_router()` calls here for `products_router`, `markets_router`, `discounts_router`.
- `FavoritesNotifier` pattern: Phase 01-02 established `AsyncNotifier` with `SharedPreferences` — QUAL-06 follows the same migration exactly (same key, same init pattern, same provider name change).

## Specific Ideas

- Base URL comment in `api_client_provider.dart`: `// Physical device: replace with http://{LAN_IP}:8000/api/v1` — makes it easy to swap during demo without forgetting why.
- FastAPI `GET /products/{id}/prices` query: `SELECT mp.*, m.name as market_name FROM market_products mp JOIN markets m ON mp.market_id = m.id JOIN products p ON mp.product_id = p.product_id WHERE p.id = (SELECT product_id FROM market_products WHERE id = :id)`. Returns current prices for all markets that carry the same canonical product.
- `uvicorn app.main:app --host 0.0.0.0 --reload` — note `--host 0.0.0.0` so physical device on same LAN can reach the server; document this in a `backend/README.md` or similar.
