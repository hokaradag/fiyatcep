### Human Verification Required

#### 1. Price History Chart — Data Accumulation Over Time

**Test:** Run backend with scheduled scraper for 2+ days, then open a product detail page and select a 7d or 30d range on the Price History chart.
**Expected:** Chart renders visible data points rather than the "Seçilen aralıkta yeterli veri yok" message.
**Why human:** Demo-volume scrape (single scrape run) produces 1-2 price points per product. All date-range windows (7d, 30d, 90d, 365d) find zero points because all prices were recorded at the same timestamp. This self-resolves as the scheduled scraper accumulates history. Human confirmed graceful empty state on 2026-04-09 — behavior is correct; this tracks future readiness.

#### 2. Turkish Character Search Normalization

**Test:** Open Products tab, type "süt" (with Turkish ü) in the search field.
**Expected:** Products with "süt" in the name appear in results.
**Why human:** `TextNormalizer.normalize()` is applied to stored product names but not consistently to the incoming search query string. Turkish IME keyboard may deliver decomposed Unicode to `TextEditingController`, causing "süt" to be sent as "st". Fix identified (apply `TextNormalizer.normalize()` to query in `productsProvider` search filter) but not implemented in this phase. Non-blocking for demo.
