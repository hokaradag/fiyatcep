## Gray Areas Identified

### 1. Backend Dev Connectivity
**Question asked:** How should Flutter reach the local FastAPI backend during dev/demo?
**User answer:** Hard-code Android emulator IP (`http://10.0.2.2:8000/api/v1`)
**Rationale:** Simple for demo phase; ngrok adds operational overhead; build-time env vars add complexity without benefit at this stage.

### 2. Non-Migros Market Data
**Question asked:** Phase 04.2 only built Migros scraper — empty markets for A101, BIM, etc. Accept or seed?
**User answer:** Accept Migros-only — empty lists are honest, no fake data
**Rationale:** Demo is Migros-centric for now; Flutter EmptyState widgets already handle 0-product markets.

### 3. QUAL-06 FavoritesStore Migration
**Question asked:** Should the FavoritesStore → Riverpod AsyncNotifier migration be included in 04.3?
**User answer:** Yes, include it
**Rationale:** Real `market_products.id` values from backend won't propagate correctly through the old singleton's dependency graph. Small task, right phase to fix it.

### 4. Verification Scope
**Question asked:** What counts as end-to-end verification?
**User answer:** Python pytest API tests + manual Flutter UAT on emulator
**Rationale:** Automated API shape validation gives confidence without full Flutter integration test suite overhead.

All 4 gray areas resolved with recommended options. No corrections or deferred ideas.
