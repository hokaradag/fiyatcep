**Response Envelope section (per D-10):**
- List responses: `{ "data": [ {...}, {...} ] }`
- Single-item responses: `{ "data": { ... } }`
- Error responses: `{ "error": { "message": "Not found", "code": "NOT_FOUND" } }`
- Note: Flutter ApiClient extracts `json['data']` in every fromJson callback. This pattern is locked.

**Endpoints to document (11 total):**

**Products (5 endpoints):**

1. `GET /products` — List all products
   - Optional query params: `marketId` (string, market slug — filters by market per D-11), `limit` (int, optional), `offset` (int, optional)
   - Response: `{ "data": [ProductItem, ...] }`
   - Each ProductItem includes embedded `priceHistory` array (per D-11) — this is NOT optional
   - Full JSON example with all fields in camelCase:
     ```json
     { "data": [{ "id": "mp-migros-001", "marketId": "migros", "name": "Aycicek Yagi 1L", "brand": "Yudum", "market": "Migros", "price": 74.95, "isDiscounted": true, "priceHistory": [{ "price": 76.50, "date": "2026-03-22T00:00:00.000Z" }, { "price": 74.95, "date": "2026-03-28T00:00:00.000Z" }] }] }
     ```

2. `GET /products/{id}` — Get single product by market_products.id
   - Path param: `id` (string) — this is `market_products.id`, same as `ProductItem.id` in Flutter
   - Response: `{ "data": ProductItem }`
   - Includes full `priceHistory` for this market_product
   - Full JSON example

3. `GET /products/search?q={query}` — Search products
   - Query params: `q` (string, required — search term)
   - Response: `{ "data": [ProductItem, ...] }`
   - Backend should search across `products.name` and `products.brand` via the canonical product
   - Each result includes `priceHistory`

4. `GET /products?marketId={slug}` — Products filtered by market (same endpoint as #1 with query param per D-11)
   - This is NOT a separate endpoint — it's `GET /products` with `marketId` query param
   - Document this as a usage example under the `GET /products` section
   - Response shape identical to `GET /products`

5. `GET /products/{id}/prices` — Cross-market prices for a product (NEW, per D-05)
   - Path param: `id` (string) — **CRITICAL: this is `market_products.id`, NOT `products.id`**. The backend resolves the canonical `product_id` from the `market_products` row, then fetches `current_price` from all `market_products` rows sharing that canonical `product_id`.
   - Response: `{ "data": [MarketPriceItem, ...] }`
   - JSON example:
     ```json
     { "data": [{ "marketId": "migros", "market": "Migros", "price": 74.95, "isDiscounted": true }, { "marketId": "a101", "market": "A101", "price": 79.90, "isDiscounted": false }] }
     ```
   - Add explicit warning box: "The `{id}` parameter is `market_products.id` (= `ProductItem.id` in Flutter). The backend resolves `products.id` internally via JOIN. Flutter never sends or receives `products.id`."
   - Per D-06: Flutter abstract method `Future<List<MarketPriceItem>> getProductPrices(String productId)` will be added to `ProductRemoteDataSource` in Phase 04.3

**Markets (3 endpoints):**

6. `GET /markets` — List all markets
   - Optional query params: `limit` (int), `offset` (int)
   - Response: `{ "data": [MarketItem, ...] }`
   - JSON example with all 7 fields in camelCase:
     ```json
     { "data": [{ "id": "migros", "name": "Migros", "description": "Turkiyenin koklu supermarket zinciri", "branchCount": 2500, "activeDiscountCount": 47, "supportsOnlineOrder": true, "hasLoyaltyProgram": true }] }
     ```

   - Response: `{ "data": MarketItem }`

8. `GET /markets/search?q={query}` — Search markets
   - Query params: `q` (string, required)
   - Response: `{ "data": [MarketItem, ...] }`

**Discounts (3 endpoints):**

9. `GET /discounts` — List all active discounts
   - Optional query params: `marketId` (string, market slug — filters by market), `limit` (int), `offset` (int)
   - Response: `{ "data": [DiscountItem, ...] }`
   - JSON example with all fields in camelCase:
     ```json
     { "data": [{ "id": "d-001", "productId": "mp-migros-001", "marketId": "migros", "productName": "Aycicek Yagi 1L", "marketName": "Migros", "oldPrice": 79.90, "newPrice": 74.95, "validUntil": "2026-04-15T00:00:00.000Z", "note": "Haftalik indirim" }] }
     ```

   - `note` field may be `null` or absent — Flutter model has `String? note`

    - Query params: `q` (string, required)
    - Response: `{ "data": [DiscountItem, ...] }`

**Error Responses section:**
- 400 Bad Request: `{ "error": { "message": "Invalid market ID", "code": "INVALID_PARAM" } }`
- 404 Not Found: `{ "error": { "message": "Product not found", "code": "NOT_FOUND" } }`
- 500 Internal Server Error: `{ "error": { "message": "Internal server error", "code": "INTERNAL_ERROR" } }`
- Note: Flutter `_handleDioException` extracts `error.message` and `error.code` from this envelope

**Notes section at bottom:**

1. **DateTime format:** All datetime fields (`date` in PricePoint, `validUntil` in DiscountItem) MUST be UTC ISO 8601 with Z suffix: `"2026-03-22T00:00:00.000Z"`. Dart's `DateTime.parse()` treats strings without Z as local time, causing incorrect date arithmetic.

2. **JSON field names:** All field names are camelCase, matching Dart field names exactly. The Flutter models use `json_serializable` with NO `@JsonKey` overrides — the Dart field name IS the JSON key. Do NOT use snake_case.

3. **ID semantics:** `ProductItem.id` and `DiscountItem.productId` both map to `market_products.id`. The canonical `products.id` is internal to the backend. Flutter never sees it.

4. **Pagination (optional):** List endpoints accept optional `limit` (int) and `offset` (int) query params. If omitted, all records are returned. This is a v2 concern (PERF-V2-01) — v1 backend may ignore these params.

5. **priceHistory embedding (D-11):** `priceHistory` array is included in ALL product responses (list and detail). Sorted ascending by `recorded_at` (oldest first). Contains all available history points for that `market_products` row.

6. **Frozen contract (D-09):** Phase 04.2 implements the backend against DB-SCHEMA.sql. Phase 04.3 implements Flutter integration against this API-CONTRACT.md. Neither phase changes the contract without explicit revision.
