# Phase 04.2: Backend Data Pipeline - Research

**Researched:** 2026-04-02
**Domain:** Python backend service — FastAPI, SQLAlchemy, SQLite, APScheduler, web scraping
**Confidence:** HIGH (stack), MEDIUM (Migros endpoint discovery), HIGH (architecture patterns)

## Summary

Phase 04.2 creates the Python backend service that lives in `backend/` within the Flutter repo. The service scrapes Migros product data, writes it to a SQLite database matching `DB-SCHEMA.sql` exactly, builds price history on every scrape run, and exposes an admin trigger endpoint for manual testing. The APScheduler embedded in FastAPI runs daily scrapes automatically.

The most significant unknown is the exact Migros internal JSON API endpoint structure. Research confirms the Turkish Migros website (migros.com.tr) loads product data via XHR/JSON calls (not server-rendered HTML), but no public documentation of these endpoints exists. The implementation plan must include a discovery/investigation task where the implementer inspects browser DevTools Network tab to identify the correct endpoint URL, required headers, and pagination pattern before writing scraper code.

For everything else — Python project setup, FastAPI + SQLAlchemy + SQLite wiring, APScheduler integration, normalized product matching, scrape logging strategy — the patterns are well-established and directly applicable.

**Primary recommendation:** Build `backend/` as a self-contained Python 3.14 project with `pyproject.toml` (no virtual environment manager required beyond pip), use APScheduler 3.x `AsyncIOScheduler` with FastAPI lifespan, use synchronous SQLAlchemy 2.0 with SQLite `check_same_thread=False`, write scrape logs to a JSON file (simpler than a DB table for demo phase), and document the Migros endpoint discovery as an explicit Wave 0 task.

### Pattern 1: FastAPI + SQLAlchemy + SQLite Setup
**What:** Single synchronous SQLAlchemy engine with `check_same_thread=False`, session-per-request via dependency injection.
**When to use:** All route handlers and scraper DB writes use this pattern.

```python
# Source: https://fastapi.tiangolo.com/tutorial/sql-databases/
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker, DeclarativeBase

SQLITE_URL = "sqlite:///./data/fiyatcep.db"
engine = create_engine(SQLITE_URL, connect_args={"check_same_thread": False})
SessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine)

class Base(DeclarativeBase):
    pass

def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()
```

### Pattern 2: APScheduler 3.x with FastAPI Lifespan
**What:** `AsyncIOScheduler` started/stopped in FastAPI's lifespan context manager. Jobs run on interval trigger.
**When to use:** Scheduler startup and graceful shutdown.

```python
# Source: https://betterstack.com/community/guides/scaling-python/apscheduler-scheduled-tasks/
from contextlib import asynccontextmanager
from apscheduler.schedulers.asyncio import AsyncIOScheduler
from fastapi import FastAPI

scheduler = AsyncIOScheduler(timezone="Europe/Istanbul")

@asynccontextmanager
async def lifespan(app: FastAPI):
    scheduler.add_job(run_scrape_cycle, "interval", hours=24, id="daily_scrape")
    scheduler.start()
    yield
    scheduler.shutdown()

app = FastAPI(lifespan=lifespan)
```

**Critical note:** APScheduler 3.x `AsyncIOScheduler` runs jobs in the same asyncio event loop as FastAPI. If the job function is synchronous (using `requests`), APScheduler 3.x will call it in a thread pool executor automatically — no extra config needed.

### Pattern 3: Canonical Product Matching
**What:** normalize_name → lookup products table → insert if missing → get product_id → upsert market_products.
**When to use:** Every scraped product record must go through this before DB insert.

```python
# Source: DB-SCHEMA.sql Notes + CONTEXT.md §D-06
import unicodedata
import re

_TR_TABLE = str.maketrans("ğşıöüçĞŞİÖÜÇ", "gsioucGSIOUC")

def normalize_name(name: str) -> str:
    text = name.translate(_TR_TABLE).lower().strip()
    return re.sub(r"\s+", " ", text)

# Lookup or insert canonical product
existing = db.query(Product).filter_by(normalized_name=norm, brand=brand).first()
if existing:
    product_id = existing.id
else:
    product = Product(id=str(uuid4()), name=name, brand=brand, normalized_name=norm)
    db.add(product)
    db.flush()  # get id without committing
    product_id = product.id
```

**Note on Turkish uppercase:** CONTEXT.md Decision [Phase 01] states "Uppercase Turkish replacements placed before toLowerCase()". The scraper receives data from Migros API (likely already in mixed case). The translate approach above handles both upper and lowercase in one pass.

### Pattern 6: Database Schema Initialization
**What:** Apply DB-SCHEMA.sql on first startup if `fiyatcep.db` does not exist. Seed markets from SQL file.
**Recommendation:** Execute `DB-SCHEMA.sql` directly via SQLAlchemy's `text()` (not ORM `create_all`) to guarantee exact schema match. Markets seed is already in `DB-SCHEMA.sql` — re-execute only if markets table is empty.

```python
import sqlite3
from pathlib import Path

def init_db(db_path: str, schema_path: str) -> None:
    if not Path(db_path).exists():
        conn = sqlite3.connect(db_path)
        schema = Path(schema_path).read_text(encoding="utf-8")
        conn.executescript(schema)  # executes all statements including seed INSERTs
        conn.close()
```

**Note:** `executescript()` is simpler than `text()` for multi-statement SQL files. It commits automatically.

### Anti-Patterns to Avoid
- **Do NOT use `create_all()` from SQLAlchemy ORM models alone** — the ORM model definitions would duplicate the schema. The frozen DB-SCHEMA.sql is the source of truth; use it directly.
- **Do NOT omit `check_same_thread=False`** — FastAPI uses multiple threads for concurrent requests; SQLite will raise `ProgrammingError` without this flag.
- **Do NOT import `products.id` as Flutter's product ID** — Flutter always uses `market_products.id`. Internal canonical `products.id` must never appear in API responses (API-CONTRACT.md §3 ID semantics).
- **Do NOT use snake_case JSON field names in API responses** — Flutter's `json_serializable` maps Dart field names 1:1 to JSON keys. `marketId` not `market_id`; `isDiscounted` not `is_discounted` (API-CONTRACT.md §2).
- **Do NOT omit `priceHistory` from product list responses** — Flutter's `@Default([])` silently deserializes missing field to empty list; chart shows no data (API-CONTRACT.md §5 note).

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| HTTP routing + validation | Custom WSGI router | FastAPI | Pydantic v2 validation, OpenAPI docs free, async handlers |
| Job scheduling | `threading.Timer` loop | APScheduler 3.x | Handles missed jobs on restart, cron/interval/date triggers, thread-safe |
| DB sessions | Manual connection management | SQLAlchemy SessionLocal + `get_db()` dependency | Exception safety, connection pooling, thread-local sessions |
| UUID generation | Custom ID schemes | `uuid.uuid4()` as TEXT | Simple, collision-free, no sequence tables needed in SQLite |
| Turkish text normalization | Ad-hoc string replace | `str.translate()` + `re.sub()` (custom) | unicodedata.normalize works for Latin diacritics but not Turkish ı↔i; must use explicit translate table (see CONTEXT.md Decision [Phase 01]) |
| Datetime formatting | Custom formatter | `datetime.now(timezone.utc).strftime('%Y-%m-%dT%H:%M:%S.000Z')` | Guarantees UTC Z-suffix required by Flutter (API-CONTRACT.md §1) |

**Key insight:** Turkish character normalization is a known pitfall (CONTEXT.md §Phase 01 decisions). Do not use `unicodedata.normalize('NFKD', ...)` — it does not handle ı→i. Use an explicit translate table.

## Common Pitfalls

### Pitfall 1: SQLite Thread Safety
**What goes wrong:** FastAPI routes run in a thread pool; SQLite raises `ProgrammingError: SQLite objects created in a thread can only be used in that same thread` when sharing connections across threads.
**Why it happens:** SQLite's default thread check mode.
**How to avoid:** Always pass `connect_args={"check_same_thread": False}` to `create_engine()`.
**Warning signs:** Intermittent `ProgrammingError` on concurrent requests.

### Pitfall 2: products.id vs market_products.id Confusion
**What goes wrong:** Scraper generates `market_products.id` incorrectly (e.g., using canonical `products.id` as the Flutter product ID), breaking all Flutter cross-market lookups.
**Why it happens:** The two-level ID indirection (D-02) is non-obvious.
**How to avoid:** The `market_products.id` format is `mp-{market_slug}-{counter}` or `uuid4()`. The canonical `products.id` is purely internal — never returned by any API endpoint. Enforce this at the schema level: scraper code must never put `products.id` into any response.
**Warning signs:** `GET /products/{id}/prices` returns 404 when Flutter sends a market_products.id.

### Pitfall 3: JSON Field Names in API Responses
**What goes wrong:** FastAPI's default JSON serialization preserves Python attribute names (snake_case), but Flutter's `json_serializable` expects camelCase.
**Why it happens:** Python convention is snake_case; Dart is camelCase.
**How to avoid:** Use Pydantic response schemas with explicit field aliases OR configure `model_config = ConfigDict(populate_by_name=True)` and define all fields with camelCase names in the schema. The response schema names must match API-CONTRACT.md exactly.
**Warning signs:** Flutter receives `null` for `marketId`, `isDiscounted`, `priceHistory` while other fields parse correctly.

### Pitfall 4: Scheduler Starts Before DB Is Initialized
**What goes wrong:** If scheduler fires immediately on startup (before DB tables exist), the first scrape run crashes with `OperationalError: no such table`.
**Why it happens:** Startup ordering — scheduler `add_job()` with `next_run_time=None` or `misfire_grace_time` might fire immediately.
**How to avoid:** Initialize DB (schema + seed) before `scheduler.start()` in the lifespan function. Add a startup delay (`next_run_time=datetime.now() + timedelta(seconds=30)`) or `misfire_grace_time=None` to prevent immediate fire.
**Warning signs:** First startup crashes; subsequent restarts work fine.

### Pitfall 5: Migros Endpoint Requires Session/Cookie State
**What goes wrong:** Replaying a captured network request fails with 403 or empty response because the endpoint requires a session cookie obtained via an earlier auth flow.
**Why it happens:** Modern retail sites use cookie-based session validation.
**How to avoid:** Test the captured request without cookies first. If it fails, use the `requests.Session()` object and first hit the homepage to obtain session cookies before hitting the product endpoint. If that still fails, use the `__NEXT_DATA__` fallback approach.
**Warning signs:** `requests.get(endpoint)` returns 403 or HTML instead of JSON.

### Pitfall 6: UTC Datetime Formatting
**What goes wrong:** Python `datetime.utcnow()` returns a naive datetime; `isoformat()` emits `2026-04-02T10:00:00` without the Z suffix. Flutter's `DateTime.parse()` treats strings without Z as local time.
**Why it happens:** Python's `utcnow()` is naive (no timezone info); `isoformat()` emits no suffix for naive datetimes.
**How to avoid:** Use `datetime.now(timezone.utc).strftime('%Y-%m-%dT%H:%M:%S.000Z')` consistently — never `datetime.utcnow().isoformat()`.
**Warning signs:** Price history chart shows wrong dates; timestamps appear shifted by UTC offset hours.

### Pitfall 7: markets.active_discount_count Not Updated
**What goes wrong:** `GET /markets` returns `activeDiscountCount: 0` for all markets even after scraping discounts, because the scraper forgot to update the denormalized counter.
**Why it happens:** DB-SCHEMA.sql notes that this field is maintained by the scraper, not a trigger.
**How to avoid:** Add an `UPDATE markets SET active_discount_count = (SELECT COUNT(*) ...)` step at the end of each scrape cycle (DB-SCHEMA.sql Notes section has the exact SQL).
**Warning signs:** Market list shows 0 discounts for all markets.

### SQLAlchemy ORM Models for DB-SCHEMA.sql

```python
# Source: DB-SCHEMA.sql (frozen spec)
from sqlalchemy import Column, String, Float, Integer, ForeignKey, UniqueConstraint
from sqlalchemy.orm import relationship
from app.database import Base

class Product(Base):
    __tablename__ = "products"
    id = Column(String, primary_key=True)
    name = Column(String, nullable=False)
    brand = Column(String, nullable=False)
    category = Column(String)
    normalized_name = Column(String, nullable=False, index=True)
    created_at = Column(String, nullable=False)

class Market(Base):
    __tablename__ = "markets"
    id = Column(String, primary_key=True)  # slug: migros, a101, bim, etc.
    name = Column(String, nullable=False)
    logo_url = Column(String)
    banner_url = Column(String)
    brand_color = Column(String)
    description = Column(String, nullable=False, default="")
    branch_count = Column(Integer, nullable=False, default=0)
    active_discount_count = Column(Integer, nullable=False, default=0)
    supports_online_order = Column(Integer, nullable=False, default=0)
    has_loyalty_program = Column(Integer, nullable=False, default=0)

class MarketProduct(Base):
    __tablename__ = "market_products"
    id = Column(String, primary_key=True)   # Flutter ProductItem.id
    product_id = Column(String, ForeignKey("products.id"), nullable=False)
    market_id = Column(String, ForeignKey("markets.id"), nullable=False)
    current_price = Column(Float, nullable=False)
    is_discounted = Column(Integer, nullable=False, default=0)
    last_scraped_at = Column(String)
    __table_args__ = (UniqueConstraint("product_id", "market_id"),)

class PriceHistory(Base):
    __tablename__ = "price_history"
    id = Column(String, primary_key=True)
    market_product_id = Column(String, ForeignKey("market_products.id"), nullable=False)
    price = Column(Float, nullable=False)
    recorded_at = Column(String, nullable=False)

class Discount(Base):
    __tablename__ = "discounts"
    id = Column(String, primary_key=True)
    market_product_id = Column(String, ForeignKey("market_products.id"), nullable=False)
    old_price = Column(Float, nullable=False)
    new_price = Column(Float, nullable=False)
    valid_until = Column(String, nullable=False)
    note = Column(String)
    created_at = Column(String, nullable=False)
    is_active = Column(Integer, nullable=False, default=1)
```

## Open Questions

1. **Migros internal JSON API endpoint URL and headers**
   - What we know: migros.com.tr uses XHR/JSON for product data (confirmed by CONTEXT.md §D-05 and community scrapers); no public documentation exists
   - What's unclear: Exact URL, required headers, pagination parameters, whether session cookies are needed
   - Recommendation: Make endpoint discovery an explicit Wave 0 task with a time-box of 1-2 hours; document fallback to `__NEXT_DATA__` parsing if cookies required

2. **market_products.id format convention**
   - What we know: Must be unique per `(product_id, market_id)` pair; Flutter uses this as `ProductItem.id`
   - What's unclear: Should it be a UUID or a deterministic slug like `mp-migros-{uuid}`? UUID is simpler; deterministic slug allows idempotent re-scraping without duplicate keys
   - Recommendation: Use deterministic slug `mp-{market_id}-{normalized_name_hash[:8]}` for idempotency OR a UUID with UPSERT logic — planner should decide

3. **Migros product category coverage**
   - What we know: Demo needs "at least 1 market" (Migros) with real data; DATA-01 says all 7 eventually
   - What's unclear: How many categories/products to scrape for a viable demo? What constitutes "enough" data for the price history chart?
   - Recommendation: Scrape 2-3 major categories (süt/dairy, ekmek/bread, yağ/oil) for ~50-200 products as a demo-viable dataset
