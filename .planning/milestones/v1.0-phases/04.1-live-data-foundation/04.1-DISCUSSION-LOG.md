## Discussion: Product Matching Model

**Question asked:** How should the backend model products across markets?

**Options presented:**
1. Global catalog + market prices (two-tier: products + market_products tables)
2. Market-first, match by name at query time
3. Market-first for now, catalog later

**User chose:** Global catalog + market prices

**Decision:** Canonical `products` table (id, name, brand, category, normalized_name) + `market_products` table (id, product_id, market_id, current_price, is_discounted, last_scraped_at). Flutter's `ProductItem.id` maps to `market_products.id` — canonical product IDs are internal to the backend.

---

## Discussion: Cross-Market Prices Endpoint

**Question asked:** How should the API serve cross-market prices for a product?

**Options presented:**
1. `GET /products/{id}/prices` — dedicated endpoint
2. Embed prices in `GET /products/{id}`
3. `GET /products?name={normalizedName}` — client-side aggregation

**User chose:** `GET /products/{id}/prices`

**Decision:** New endpoint returns `List<MarketPriceItem>` sorted by price. Backend resolves canonical product from `market_products.id`, fetches all market prices. New method `getProductPrices(String productId)` added to `ProductRemoteDataSource` interface.
